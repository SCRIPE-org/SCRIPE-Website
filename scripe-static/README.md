# SCRIPE — static website

The SCRIPE public website as plain **HTML + CSS + vanilla JavaScript**.

No framework, no build step, no runtime dependencies. Open the files or serve
the folder and it works.

---

## Run it locally

```
node tools/serve.mjs
```

Then open <http://localhost:5173>.

Any static server works equally well — `python -m http.server`, `npx serve`,
nginx, Netlify, S3, GitHub Pages. The included server exists only so the site
can be previewed without installing anything.

> Opening `index.html` directly from disk (`file://`) also works: every path in
> the site is relative. A server is still preferable, because `file://` blocks
> the `fetch` used by the contact form's optional endpoint.

## Deploy it

Upload the whole folder. There is nothing to compile.

Before going live, stamp the production domain into the canonical, Open Graph,
sitemap and robots entries:

```
node tools/set-domain.mjs https://www.your-domain.com
```

Every page ships with a `__SITE_URL__` placeholder rather than a guessed
hostname, so nothing can go live pointing at the wrong domain. The command is
re-runnable — pass a different URL any time to retarget.

## How it works

**Navigation** is ordinary `<a href="page.html">`. There is no router. Back,
Forward, direct URLs, deep links and middle-click all behave exactly as the
browser intends.

**The navbar and footer** are generated by `js/navbar.js` from a single
definition at the top of that file, so the markup is never duplicated across the
twelve pages. Add a route there and it appears everywhere.

On the home page the bar stays transparent for the **entire** hero and becomes
the frosted bar exactly when the hero leaves the viewport — observed with
`IntersectionObserver` against the hero element itself, never a pixel threshold.
The two states are `navbar--hero` and `navbar--scrolled`, and neither changes the
bar's height. Scrolling back up returns it to transparent. Every other page is
frosted from the first paint.

**The hero** is a direct port of the approved camera implementation. The six
shots, the cubic easing, the 0.075 smoothing constant, the cover-fit maths, the
caption cross-fade windows, the scene rail, the drone drift and the pointer
parallax are unchanged. The camera moves over **one intact photograph** — there
is no layer separation.

**Theme** is two designed sets of semantic tokens in `global.css`: `:root` carries
Light, `[data-theme="dark"]` carries Dark. No stylesheet is duplicated and no
colour is inverted — both are authored. The choice is stored in `scripe-theme`,
falls back to `prefers-color-scheme`, and is applied by a tiny inline script in
each `<head>` before the first paint, so there is no flash. The swap transitions
only the properties that repaint, for 240ms.

**Language** is English in the HTML and Arabic in `js/lang-ar.js`. Elements carry
`data-i18n="key"`; on load the engine captures each element's English text, so
switching to Arabic swaps it and switching back restores the original — there is
no English dictionary to drift out of sync. `<html lang>` and `<html dir>` are
set by the same head script, and the choice is stored in `scripe-language`.
Theme and language are independent: changing one never resets the other.

**RTL** is real, not a mirrored page. The layout was already built on logical
properties (`inset-inline`, `padding-inline`, `text-align: start`), so Arabic
flips correctly on its own; only directional icons carry an explicit flip. The
hero is the deliberate exception — its camera uses physical `left`/`top` because
those are coordinates inside the photograph, which is never mirrored. Only the
hero's captions and scene rail flip.

**Scroll reveals** are one `IntersectionObserver` in `js/reveal.js`. Any element
marked `data-rv` reveals; `data-bar`, `data-fill`, `data-spark` and `data-count`
drive the chart primitives. Adding a section costs no extra JavaScript.

**Styling** lives in the five stylesheets. The design system is CSS custom
properties (`--surface-page`, `--accent-primary`, `--ease-enter`, …) defined in
`global.css` and used everywhere. Repeated component patterns are named classes
in `pages.css`; a handful of per-instance values (one grid span, one accent
colour) remain as HTML `style` attributes, which is plain static HTML.

**Every script is `defer`red** and does nothing until `main.js` calls it, and
`main.js` only calls the modules whose markup is actually on the page.

## The contact form

The form validates in the browser and then says plainly that the site is not yet
connected to a live inbox. **No endpoint is faked.**

To wire a real one, set `ENDPOINT` at the top of `js/contact.js` to your form
handler's URL. The form will POST JSON and switch to the delivered wording on a
2xx response.

Never put an API key in `js/contact.js` — anything shipped to the browser is
public. Use a provider that accepts unauthenticated form posts, or put your own
endpoint in front of the credential.

## What is deliberately not filled in

None of the following is invented, and each shows an honest placeholder until
you supply the real value:

| What | Where |
| --- | --- |
| Production domain | `__SITE_URL__` — run `tools/set-domain.mjs` |
| Social profile URLs | `SOCIAL` in `js/navbar.js` — listed as "not published yet" |
| Privacy / Terms documents | Footer links resolve to the Company page's placeholder note |
| Contact email and phone | Contact page states the channel is not published yet |
| Registered legal entity | Footer shows "© SCRIPE" |

## Adding or changing copy

English lives in the HTML. To change a string, edit it in the page — and if it
carries a `data-i18n` key, update the matching entry in `js/lang-ar.js`. A key
with no Arabic entry falls back to English rather than showing the key, so a
missing translation degrades quietly instead of breaking the page.

Strings built in JavaScript (validation messages, the navbar, the footer) use
`SCRIPEI18n.t(key, englishFallback)` and semantic keys — `nav.*`, `ui.*`,
`footer.*`, `form.*`.
